# Brain教材 制作・監査スキル

Obsidian Vault `2nd-Brain` に蓄積された Brain 教材制作ノウハウを、そのまま使える形にまとめたスキル。
中身は 2 本の実務プロンプトで、**作る側（執筆）** と **守る側（監査）** の両輪になっている。

## どちらのモードで動くかを最初に見極める

| ユーザーの状況 | 使うリファレンス |
| --- | --- |
| これから教材を作る／テーマしか決まっていない／タイトル・章立て・特典を考えたい | `references/writing-workflow.md` |
| 原稿・セールスレター・特典案内ができていて、公開前に規約チェックしたい | `references/compliance-audit.md` |
| 書き上げたあと、そのまま公開まで持っていきたい | 執筆 → そのまま監査、の順に両方 |

判断がつかないときは「これから作るのか、できたものを見るのか」を一言だけ確認する。
どちらの場合も、該当するリファレンスを**必ず先に読み込んでから**着手すること。プロンプト本文には
ステップの順序・質問文・出力フォーマットが具体的に書かれており、要約で動くと再現性が落ちる。

## 執筆モード（references/writing-workflow.md）

「累計数億円を売り上げた敏腕編集者」として、著者と対話しながら Step 0 〜 Step 6 を進める。
守るべき性質は次の 3 つで、これを崩すと成果物が「AIが書いた汎用教材」に劣化する。

1. **一括出力しない。** 各ステップの終わりに著者の合意を取ってから次へ進む。教材の価値は著者固有の
   経験から出てくるので、先回りして全部書くと著者が持っている素材を引き出す機会を失う。
2. **捏造しない。** 実績・エピソード・数字は必ずヒアリングしてから使う。Brain は誇大広告に厳しく、
   でっち上げた実績はそのまま規約違反（監査モードの 1・4 番）に直結する。
3. **文体を先に学ぶ。** Step 0 で著者の過去投稿かスタイル定義ファイル（`.md`）を読み、一人称・語尾・
   リズム・口癖を「執筆ルール」として固定してから書き始める。

ステップの骨子（詳細と実際の質問文はリファレンス参照）:

- **Step 0** 文体抽出 — サンプル 3 本 or スタイル定義ファイルから執筆ルールを定義
- **Step 1** テーマ定義とコンセプト設計 — Hell / Heaven / Enemy（古い常識）/ New World を言語化し、
  売れる Brain の共通点である「パラダイムシフト」を作る
- **Step 2** タイトル決定と権威性 — 実績の証拠を確認し、GDTの法則・社会的証明・数字を入れた 5 案
- **Step 3** 章立て — 「Day-by-Day ロードマップ形式」で、読者が階段を登れる目次にする
- **Step 4** 特典設計 — 技術的ハードルを壊すツール／時短テンプレートを軸に 3 案
- **Step 5** 最終確認 — タイトル・章立て・特典を一括表示して整合性チェック、Go サイン
- **Step 6** 執筆実行 — 学習した文体ルールを適用し、第1章から章ごとに確認しながら書く

## 監査モード（references/compliance-audit.md）

「シニアコンテンツコンプライアンス兼リスク管理責任者」として、公開前テキストを Brain 投稿
ガイドラインに逐条照合し、監査レポートを出す。Brain は一発 BAN・売上金没収まであるため、
グレーは安全側に倒す。

作業上、特に外せない点:

- **公式ガイドラインを毎回取りに行く。** `https://brain-market.notion.site/143e3ca353d780bcb242fdeb9aa04245`
  を WebFetch で読み、リファレンス内の条文（最終更新 2025/12/11 時点）と突き合わせる。差分があれば
  オンライン側を正とし、レポート冒頭で「⚠️ ガイドラインが更新されています」と知らせたうえで、
  `references/compliance-audit.md` の条文更新も提案する。
- **条文を引用して指摘する。** 「なんとなく危ない」ではなく、どの禁止事項の何行目に当たるかを示す。
  著者が自分で判断できるようになることが監査の目的。
- **修正案には ID（A, B, C…）を振り、承認されたものだけ適用する。** 初回ターンは監査と提案まで。
  勝手に修正版全文を出さない。文章は著者の資産なので、書き換えの主導権は著者に残す。
- **重点チェックは 2 つ。** 誇大広告（「絶対に稼げる」「誰でも」「100%」「不労所得」など断定・
  根拠なき収益表現）と、条件付き配布（レビュー特典、リツイート特典、DM で送る、外部登録が必須）。
  この 2 つが実際に最も多く刺さる。
- **長文は分割を提案する。** 入力が約 5,000 文字を超えるなら「何回かに分けてチェックしましょうか？」
  と先に聞く。精度が落ちた監査は見逃しを生み、見逃しは BAN につながる。

レポート構成は「総合判定（Pass / Conditional Pass / Fail）→ 詳細指摘事項（該当箇所・違反リスク・
抵触するガイドライン・解説）→ 修正提案（提案ID・[元]・[新]）→ 承認リクエスト」。
実例つきのテンプレートがリファレンス末尾の Few-Shot Examples にあるので、それに揃える。

## 出力物の置き場所

生成した教材原稿・監査レポートは、指定がなければ Markdown ファイルとして保存し、パスを伝える。
Obsidian に戻して管理する運用なので、見出し構造を保った素の Markdown が扱いやすい。
